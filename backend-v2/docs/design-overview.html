§0 你拍板的四个决定

1 · 从零重写 v2

全新代码库 backend-v2/，旧 backend/ 只读留作母本，切换完成后归档。

2 · 全量替代

公网 API（登录/聊天/社交/私信/订阅/徽章/文章/审核）全部重建；站点 docs/ 一行代码不改，路径保持 /api 不变。

3 · AI 先做架构

界面 + API + 权限 + 知识库检索做真；LLM 走 provider 接口，密钥没配时优雅返回「未配置」，配好即通。

4 · 第一波全选

地基 + 用户中心 + 客服升级 + 财务扩展 + Dashboard 分析，分 5 波交付（W0 ✅ → W5）。

§1 数据库 · 16 张表

4 个迁移文件一次设计到位（无旧版式的先建后重建）；主键带前缀编号（USR-/STAFF-/AUD-…），金额分两个平面（机器事件存整数微元、人工记账存 2 位小数+币种）。

002 · 工作人员与权限（RBAC） 6 张表

staff 独立于 users；一人可多角色；角色矩阵在数据库里、每请求现查
表用途关键点
staff工作人员real_name（真名）内部字段——结构上永不序列化出接口；alias 公开化名；is_active 停用开关；工时/时区/语言

003 · 审计日志 1 张表

哈希链 + 数据库触发器强制「只准追加，不准改、不准删」
表用途关键点
audit_log一切状态变更的不可篡改记录每一行 hash = 上一行 hash + 本行内容的指纹，整链可验证；记录谁（工作人员/系统/Stripe/定时任务）、做了什么、改前改后、原因、IP；被拒绝的操作也记录（result = denied）

004 · 平台设置 2 张表

强类型设置表 + 运行时键值表 —— 预算红线就住在这里

kv运行时键值只放 cron 上次运行时间之类，不进界面

§4 关键决策 + AI 红线

D1 金额双平面 — 机器事件存整数微元（无浮点误差）；人工记账存 2 位小数 + 显式币种，统一走 money.js。
D2 双会话 — 公网 mn_session 与工作人员 sc_session 完全分离，互不相通。
D3 路径 — 管理 API 全部 /api/staff/*；公网 /api/* 与 v1 逐字一致。
D4 管理员只在 staff 表 — users.role 数据库层面锁死只能 'user'，不可能再出现「普通用户成管理员」。
D5 AI 客服日志记问答内容 — 规格 §14 硬性要求；查看此日志的权限（cs.logs.view）单独收紧。
D6 新增社区表 — 评论/百科/点赞/收藏/分享/访问统计（v1 没有，公网新端点全部是加法）。
D7 限流持久化 — SQLite 滑动窗口，重启不清零。
D8 预算进设置表 — 红线 30/20/10/60 元不变；≥80% 预警邮件、≥100% 降级（绝不硬下线）。
D9 分析读时聚合 — SQL 现算，不养一张会过期的汇总表。
D10 IP 地理可选 — 2 秒超时失败跳过；IP 只作风险信号，不单独判盗号。
D11 套餐沿用 — basic/premium/ultra + 两款包价 SKU；区域定价各定各的价，禁止汇率换算。
D12 审计哈希链 — 每行链上一行指纹 + 触发器强制 append-only。
AI 红线（§20 禁止清单的代码落地）
  • ① AI 没有认证主体 —— 数据库/接口层它就不是一个「账号」，天然做不了管理操作
  • ② /staff/ai/* 端点只返回数据；源码测试断言 AI 模块里没有任何写库语句
  • ③ 封禁/删用户、改权限、批准退款、改价格/财务/规则、分配管理员、关闭工单、发人工回复 —— 全部只有持权限的人类能做
  • ④ AI 的回复草稿必须先经人类点「发送」+ 过权限检查，才进工单
  • ⑤ 退款审批键（refunds.approve）从设计上就没有任何 AI 旁路
审阅提示：现在改表结构/权限/路径最便宜 —— W1 开始往上盖公网模块的代码之后，改动成本会变大。 特别说明一处与计划书的差异：权限键实际是 42 个，计划书 §4 写的是 41——以迁移文件里的 42 为准，测试已锁定，偏差已记入日志。 看完觉得哪张表、哪个角色、哪条路径要改，直接跟我说就行 (｡•̀ᴗ-)✧
