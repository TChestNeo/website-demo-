1. Bug fix — Flag source modal unreachable
   - User report: clicking a National Flag card never opened the
     flag-source modal.
   - Root cause: the drag mouseup stamped dataset.justDragged='1'
     unconditionally, and the flag-card click listener bails on that
     marker. A plain click always fires within the 300ms window after
     its own mouseup, so the modal was unreachable. (Confirmed via
     headless probe: 3 fails; the bug predates v8 — identical stamp in
     the v7.4 backup.)
   - Fix: the stamp + 300ms clear now live inside `if (st.moved)` —
     only real drags suppress the click. Verified 5/5.
   - Note: virtual time does NOT advance during synchronous scripts,
     which caused a false negative in the probe's "bare click" control.

2. FluidCanvas v9.1 — Bitmap Auto-Fit + Aspect Lock
   - User request: cards auto-fit the size of an image set on them;
     after fitting they can no longer be stretched arbitrarily.
   - Design (confirmed): all cards with bitmap images (flag + gallery
     + any non-content card with a background image); fit = natural
     pixel size, downscaled proportionally only if bigger than the
     page (minus 16px margins); after fit the card CANNOT stretch in a
     single direction (edge handles hidden) but CAN scale
     proportionally via the 4 corner handles (opposite corner fixed).
   - Markers: dataset.aspectLock/aspectRatio/fitW/fitH;
     isAspectLocked() excludes content/text cards; stripe flags have
     no intrinsic size and never lock.
   - fitCardToImage: measures naturalWidth/Height on image load;
     scale = min(1, (page.w-32)/nw, (page.h-32)/nh); writes exact px;
     colSpan/rowSpan become display hints only.
   - setCardImage: onload attached BEFORE src (data:/cached images can
     fire immediately) with triple guard — card still connected, img
     still the card's current one, and not already locked (draft
     restore sets saved px synchronously, so re-measuring is skipped).
   - Locked resize: corner drag → one scale factor from the corner-ray
     projection f = 1 + (dirX·w·lx + dirY·h·ly)/((w²+h²)/2); floor
     max(cs/w, cs/h) keeps both dims >= 1 cell; newH = round(newW /
     stored ratio) — zero cumulative drift; setCardSize bypassed
     (it would re-quantize the fitted pixels to grid spans); the v9
     opposite-corner center-shift math is reused unchanged.
   - Unlock snaps back to grid: setCardStripes / applyCardBackgroundColor
     / clearCardBackground call clearAspectLock(card, true) which
     immediately re-quantizes to the span hints — otherwise the
     in-session pixel size would disagree with what a reload restores
     (spans only). setCardImage skips the snap (refit is imminent).
   - Silent resetters guarded: positionCardSilent keeps fitW/fitH px
     for locked cards → applyPresetCardPositions / refitColumns /
     preset switches preserve fitted sizes.
   - Escape mid-resize now COMMITS like mouseup (was: discard) —
     otherwise dataset.x/y went stale while the visual size changed
     and the next reload misplaced the card (pre-existing bug made
     load-bearing by the locked path).
   - Persistence (draft v stays 9 — all fields additive): saveDraft
     adds aspectLock/aspectRatio/fitW/fitH; non-flag cards now also
     persist their background image imgSrc (previously flag-only, so
     gallery cards lost their image on reload); loadDraft restores
     the exact fitted px synchronously; saveCurrentPresetCards keeps
     the lock fields; getCardFingerprint includes the markers so
     fit/locked-resize/unlock trips autosave.
   - Badge + self-check: FC v9.1 / ready (v9.1).

4. Testing notes (environment facts learned this day)
   - Page width is dynamic: at 1280x900 the page is 44 cols
     (page.w = 966), not 21 cols/460 — always derive expectations
     from window.pageSize() instead of hardcoding.
   - beginResize acts on whatever card is selected — tests must
     selectCard explicitly before every beginResize call.
   - Test-order pollution: artificial spans written by one test leak
     into the draft and change round-trip expectations — restore real
     hint spans after such probes.

5. Known Issues / Pending
   - Real-browser verification pending (headless cannot simulate IME):
     Chinese IME typing inside content cards; corner-resize feel on
     locked cards (incl. rotated); fit correctness with real photo
     uploads (JPEG orientation etc.).
   - Locked cards on a smaller preset can exceed the page (fitted px
     is set-time-only) — boundary centers them; user can corner-resize
     to refit. Accepted behavior.
